# Colab で学習を回す手順

Colab で Shikibu の学習を最初から回すときの、順番どおりの手順です。
切れたときの対処や注意は `docs/OPERATIONS.md`、設定の意味は `docs/CONFIG.md` にあります。

ノートブックは `notebooks/colab_train.ipynb` です。以下の「節 1」「節 2」などは、そのノートブックの見出しの番号を指します。
学習データ・出力先・Drive のフォルダ名は、利用者が決めます。この文書の例では `<…>` の目印で書いています。

> この手順のうち、Colab の上で動く部分は、この開発環境では実行していません（`docs/OPERATIONS.md` の 10 を参照）。ノートブックのコマンドの一部は、同じ内容を手元の Linux で実行して確かめています。

---

## 0. 用意するもの

| 用意するもの | 置き場所の例（`MyDrive` からの相対パス） | 無いとき |
|---|---|---|
| 学習用の PSV（1局面 40 バイトのファイル群） | `<学習データのフォルダ>/*.psv` | **学習できない**。設定セルの `DATA_GLOB` にそのパスを書く |
| リポジトリ（Shikibu） | `<リポジトリを置くフォルダ>/Shikibu` | 節 3 が `REPO_URL` から取得する |
| wheel（`shk_feat-*.whl`、Rust の拡張） | `<wheel を置くフォルダ>` | 節 4 が作って保存する（初回だけ時間がかかる） |
| 出力（学習の結果） | `<出力のフォルダ>/<学習の名前>/` | 節 5 が作る |

- PSV は、評価値（手番側から見た cp）と勝敗（手番側から見た 1・0・−1）を持つ形式です（`docs/FORMATS.md` の 1）。
- 1つの学習に複数のファイルを使えます。`DATA_GLOB` は glob で書きます（例：`…/*.psv`）。
- 同じ学習データで2つの教師のデータを混ぜるときは、`docs/OPERATIONS.md` の 5 と 6 を先に読んでください。

---

## 1. 最初の1回の準備

1. Colab で `notebooks/colab_train.ipynb` を開く。
2. **ランタイム → ランタイムのタイプを変更** で、ハードウェアアクセラレータを **GPU** にする。
3. 上の表の学習データを Drive に置き、パスを確かめる。

ここから先は、ノートブックの節を上から順に実行します。

---

## 2. 節の順番と、やること

### 節 1：Google Drive をマウントする

- 初回は認証画面が出るので、表示に従って許可します。
- 再接続のたびに実行します（`docs/OPERATIONS.md` の 2）。

### 節 2：設定（ここだけ書き換える）

設定セルに、利用者ごとの値をまとめてあります。`<…>` の目印を、自分の環境の値に書き換えてください。
目印が残っていると、次の節の最初で「<…> を書き換えてください」と表示されて止まります。

| 変数 | 意味 |
|---|---|
| `REPO_URL` | リポジトリの取得元（Drive に `REPO` が無いときだけ使う） |
| `BRANCH` | 取得するブランチ（既定は `main`） |
| `REPO` | Drive 上のリポジトリの場所 |
| `WHEEL_DIR` | wheel の保存先 |
| `DATA_GLOB` | 学習用の PSV のパス（glob） |
| `OUT_ROOT`・`RUN_NAME` | 出力は `OUT_ROOT/RUN_NAME` に作られる |
| `TEMPLATE` | ひな形の設定。RayPair_v0 は `configs/colab_v0.toml`、RayPair_v1 は `configs/colab_v1.toml` |
| `CACHE_DIR` | Colab のローカルの一時コピー先（既定は `/content/shk_cache`。Drive には置かない） |
| `SESSION_MAX_STEPS` | このセッションで区切る通算の更新回数。`None` なら設定の `max_steps` |

- `SESSION_MAX_STEPS` は**通算**の更新回数の上限です。1回のセッションで区切るときは、その時点の通算の数を入れます。例：最初のセッションは `60000`、次は `120000`。
- `total_steps`（学習率の減衰の長さ）は変えないので、区切って続けても学習率は同じ曲線をたどります。

### 節 3：リポジトリを取得（または更新）する

- `REPO` があれば `git pull` で更新します。無ければ `REPO_URL` から `git clone` します。
- 取得するブランチは `BRANCH` です。

### 節 4：wheel（`shikibu_feat`）をインストールする

- `WHEEL_DIR` に `shk_feat-*.whl` があれば、それを入れます（数秒）。
- 無ければ、Rust を入れて `maturin build --release` で wheel を作り、`WHEEL_DIR` に保存してから入れます（初回だけ）。
- 節の最後に、PyTorch の版、GPU が使えるか、論理コア数を表示します。**GPU が「なし」と出たら、ランタイムの種類を確かめてください。**

Rust のソースを変えたときは、`WHEEL_DIR` の wheel を消してから、節 4 を実行し直します。
wheel の名前には Python の版が入ります（例：`cp313`）。Colab の Python の版が変わると、古い wheel は入りません（確かめた：別の版の名前の wheel は `pip` が「対応していない wheel」として拒否します）。そのときは、wheel を消して作り直します。
節 4 は、保存された wheel のうち一番新しいものを選ぶだけで、Python の版は見ません（`docs/DEVELOPMENT.md` の 5.4）。

### 節 5：設定ファイルを出力フォルダに書き出す

- ひな形（`TEMPLATE`）の `<…>` の値を、設定セルの値で置き換えて、`OUT_ROOT/RUN_NAME/config.toml` に書き出します。
- 学習はこの書き出したファイルを使います。リポジトリのひな形は変わりません。
- 書き出したファイルは Drive に残るので、再開のときもそのまま使えます。
- 節の最後に、学習用の PSV の数、出力先、`checkpoint.pt` の有無、バッチの大きさ、総更新回数を表示します。

### 節 6：学習を裏で開始する（`mon.start`）

- 学習は裏のプロセスで始まり、このセルはすぐ終わります。
- `checkpoint.pt` があれば、自動で `--resume` を付けて続きから回します。無ければ最初から回します。
- 同じ出力フォルダで学習が実行中なら、学習器はロック（`train.lock`）で断ります。次の節の表示に理由が出ます（`docs/OPERATIONS.md` の 3）。
- `FORCE_UNLOCK` は、切断の直後で、学習が動いていないのにロックが残っているときだけ `True` にします。
- 止めるときは `mon.stop()` を実行します。最後の保存より後の分は失われます。

### 節 7：進み具合を表示する（`mon.watch`）

- 15 秒ごとに、段階（データの確認・準備・学習中）、進捗、残り時間、速さ、損失のグラフを表示します。
- 表示の■（停止）は、表示だけを止めます。学習は続きます。もう一度このセルを実行すると表示が戻ります。
- **学習の間は、このセルを動かし続けてください。** 別のセルを実行したら、すぐにこのセルを実行し直します（`docs/OPERATIONS.md` の 1）。
- 「起動できない：同じ出力フォルダで学習が実行中」と出たら、もう1つの学習が動いています。止めてから始め直すか、`docs/OPERATIONS.md` の 3 を読んでください。

表示される段階の意味は次のとおりです。

| 表示 | 意味 |
|---|---|
| 準備中：データの確認（勝敗の記録・局面の抜き出し） | 新規の学習の最初。全学習ファイルから局面を抜き出して、勝敗を確かめる |
| 準備中：eval_scale を推定中 | `eval_scale` が `"auto"` のとき |
| 準備中：Drive から先読み中 | `cache_dir` へのコピー（ファイルの大きさを表示する） |
| 準備中：シャッフルバッファを充填中 | `shuffle_buffer` を満たしている |
| 学習中 | 通常の学習 |
| 完了 | `max_steps` に達して、保存して終わった |
| 停止（手動） | `mon.stop()` で止めた |
| 起動できない：同じ出力フォルダで学習が実行中 | ロックで断られた |
| 異常終了（終了コード …） | 学習のプロセスが失敗した。最後の出力が表示される |

### 節 8：重みファイルを書き出す（RayPair は `.shk`、HalfKP は `nn.bin`）

- 学習の途中の `checkpoint.pt` からでも書き出せます（保存は一時ファイルから改名するので、書き出し中に壊れることはありません）。
- 出力先は `OUT_DIR/RUN_NAME.shk`（RayPair）か `OUT_DIR/nn.bin`（HalfKP）です。
- **HalfKP のときは**、表示される `FV_SCALE=<整数>` を控えてください。やねうら王・Nuenagon の `FV_SCALE` に、この値を設定します。節 9（`quantsim`）は HalfKP では対象外です（書き出しのときに読み直して確かめています）。
- 書き出したあと、同じファイルを読み直して、ヘッダ・CRC32・全テンソルが一致するかを確かめています。一致しなければ、エラーで止まります。
- 終了コードが 0 なら、書き出しは成功です。

### 節 9：量子化の確認（`quantsim`）

- 整数の計算（エンジンが使う量子化、§E4）と、float32 の重みとの差を表示します。
- 表示される「z の差」「評価値の差（cp）」「損失」を控えます。
- **注意**：節 9 は、学習に使ったファイルの先頭で行います。本当の確認には、学習に使わなかった局面（検証用）を `--psv` で指定します（検証用のデータは、今は用意していない）。

---

## 3. 学習が終わったら

1. 出力フォルダ（`OUT_ROOT/RUN_NAME/`）に、次のファイルがあることを確かめる。
   - `RUN_NAME.shk`：エンジンに渡す重み
   - `checkpoint.pt`・`log.jsonl`・`status.json`・`config.toml`
2. `status.json` の `phase` が `done` であることを確かめる（`done` なら `max_steps` に達して、保存して終わっている）。
3. エンジン（Nuenagon）に渡すときは、`.shk` を `eval/nuenagon.shk`（既定の場所。§E2.2）に置くか、USI オプション `EvalFile` で指定する。
4. エンジン用の正解データ（N3 で使う）は、次の節の手順で作ります。

---

## 4. エンジン用の正解データを作る

Colab でも手元の PC でも作れます。`shikibu_feat`（wheel）と `cshogi` が要ります。

```
python tools/make_engine_golden.py --shk <RUN_NAME>.shk --out golden.json --n 1000 --seed 1
```

- `--n` は局面数、`--seed` は局面を作る乱数の種です。同じ種でも、`cshogi` の版が違うと局面が違う可能性があります（確かめていません）。
- 出力の JSON には、`.shk` の SHA-256（`shk_sha256`）が入ります。エンジン側で、同じ `.shk` を使っているかを確かめられます（形式は `docs/FORMATS.md` の 6）。
- `cp` はクリップしていません。エンジン側で、詰みの値と重ならないように収めてください。

手元の PC で動かすには、`README.md` の「手元の PC で動かす」の手順で仮想環境を作ってください。

---

## 5. 途中で切れたとき

1. `docs/OPERATIONS.md` の 2（切れたあとの再開）に従う。
2. 要点：
   - 節 1（Drive）→ 節 4（wheel）→ 節 3（リポジトリ）→ **節 5（設定の書き出し。これを飛ばさない）** → 節 6（`mon.start`。自動で再開）→ 節 7（`mon.watch`）の順に実行する。
   - 最後の保存より後の分は失われる（既定では最大約 30 分）。
   - 切断の直後で、ロックが残っていて学習が動いていないときだけ、節 6 の `FORCE_UNLOCK` を `True` にする（`docs/OPERATIONS.md` の 3）。

---

## 6. 設定を変えたいとき

- 節 2 の `SESSION_MAX_STEPS` で、このセッションの区切りを変えられます（学習率は変わりません）。
- そのほかの設定（バッチの大きさ、学習率、スレッド数など）は、リポジトリのひな形（`configs/…toml`）を直すか、節 5 で書き出された `config.toml` を直してから、節 6 を実行し直します。
  - ただし、節 5 を実行すると `config.toml` は設定セルの値で作り直されます。直した内容を残したいときは、ひな形のほうを直してください。
  - **途中で変えてよいもの**：`max_steps`（通算の上限）、`save_every_minutes`、`progress_every_sec`、`num_threads`、`torch_threads`。
  - **途中で変えてはいけないもの**：`network`（`checkpoint.pt` と合わなくなる）、`lam`、`train_glob` のファイル数、`eval_scale`（無視される。変えたいときは別の出力フォルダで始める）。
  - 詳しくは `docs/CONFIG.md` の「再開（`--resume`）のときの規則」を参照してください。
- 別の設定で最初から学習するときは、`RUN_NAME` を変えます（別の出力フォルダになる）。同じフォルダに `checkpoint.pt` が残っていると、`--resume` なしでは止まります。
